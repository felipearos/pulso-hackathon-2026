## What landed

The `whatsapp` port's real Meta WhatsApp Cloud client, `src/whatsapp-cloud.ts`, wired into
`realPorts()`. Audio is uploaded to `/media` and sent as `type: "audio"` with `voice: true`, so
it arrives as a nota de voz (non-OGG is refused before any request is made); text; image with an
optional caption. The 24 h window is opened by `recordInbound`; closed or unknown means the
approved `audio_noche` template is sent and the free-form message is dropped. Failures land in
`failures` and in the log with the token redacted, retried at 1 s and 2 s, never into the
madrugada (00:00–05:30 America/Santiago, checked on both sides of the wait, time taken from the
clock port per ADR 0002). Plus a real smoke test gated on `WHATSAPP_SMOKE` and six rows in the
CLAUDE.md variables table.

All three acceptance criteria are covered by tests: the voice-note send pins the `voice: true`
flag in the request body, the out-of-window path asserts the template, and the failure path
asserts both the `failures` entry and that a retry is never scheduled inside the madrugada.

## Key decisions

- `recordInbound` was promoted into the `WhatsApp` port type in `src/ports.ts` (and into
  `FakeWhatsApp`). Without it no production code could open the window, so every real send would
  have gone out as the template. This is the one shared file the ticket touches.
- `MissingEnvError` moved to `src/missing-env.ts`, re-exported from `real-ports`, to break the
  `real-ports` ↔ `whatsapp-cloud` import cycle the first wiring created.
- The window is in-memory on purpose: persisting it needs a migration, and the migration list
  belongs to #22/#23.
- The smoke test gates on `WHATSAPP_SMOKE`, which deliberately lives in no Doppler config. The
  credentials do live in `dev`, so a plain credential gate would have made every loop's
  `bun run test` send a real WhatsApp message.
- Declined: moving the non-OGG check after the window check (the order is deliberate — nothing
  should be uploaded for audio we would refuse); not retrying 4xx (not a spec violation).

## Codex findings

- **P1 `whatsapp-cloud.ts:222` — real, fixed in `99ee2bd`.** Meta's audio-messages docs give the
  `audio` object a `voice` boolean, and only `voice: true` makes an OGG/Opus arrive as a nota de
  voz. Without it the whole «audio de la noche» arrived as a plain audio attachment — the
  ticket's central promise. Worth recording: the happy-path test passed in full while the
  feature's one visible promise was broken, because nothing asserted the flag.
- **P2 `whatsapp-cloud.ts:208` — rebutted, no code change.** Requiring the literal `codecs=opus`
  in the mimeType would reject the only audio the system actually produces: ElevenLabs asks for
  `output_format=opus_48000_64` and labels it `audio/ogg` with no `codecs` parameter
  (`src/voice/elevenlabs.ts:124`), and `FakeVoice` does the same.
